¿QUÉ ES BLUETEAMBOTLITE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

BlueTeamBotLite es una herramienta de CIBERSEGURIDAD DEFENSIVA que:

✓ Escanea automáticamente tu red en busca de vulnerabilidades
✓ Detecta puertos abiertos, servicios desactualizados y configuraciones inseguras
✓ Genera reportes profesionales en PDF y CSV
✓ Guarda histórico en base de datos para análisis temporal
✓ Compara períodos de tiempo para ver mejoras o nuevos problemas
✓ Alerta sobre configuraciones prohibidas (puertos peligrosos, protocolos antiguos)

¿CÓMO FUNCIONA? (ARQUITECTURA)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. ESCANEO (scan.py)
   ├─ Lee targets.yaml para saber qué IPs escanear
   ├─ Usa NMAP para detectar:
   │  ├─ Puertos abiertos (21, 22, 80, 443, etc.)
   │  ├─ Servicios corriendo (SSH, HTTP, FTP, etc.)
   │  └─ Versiones de software (OpenSSH 7.4, Apache 2.4, etc.)
   └─ Guarda resultado en JSON bruto

2. EVALUACIÓN DE REGLAS (rules.py)
   ├─ Lee rules.yaml con políticas de seguridad
   ├─ Compara cada hallazgo contra las reglas:
   │  ├─ ¿Puerto prohibido? → SEVERIDAD HIGH
   │  ├─ ¿Versión desactualizada? → SEVERIDAD MEDIUM
   │  └─ ¿Protocolo inseguro (TLS 1.0)? → SEVERIDAD MEDIUM
   └─ Marca cada hallazgo con razones específicas

3. COMPARACIÓN (diff.py)
   ├─ Compara contra el escaneo anterior (baseline.json)
   ├─ Detecta:
   │  ├─ NEW: Nuevos problemas que antes no existían
   │  ├─ CHANGED: Problemas que empeoraron o mejoraron
   │  └─ SAME: Problemas que siguen igual
   └─ Solo reporta lo nuevo y cambiado

4. BASE DE DATOS (db/models.py + queries.py)
   ├─ Guarda TODOS los escaneos en SQLite (data/bluebot.db)
   ├─ Permite consultas como:
   │  ├─ "Muéstrame escaneos entre 01-Nov y 30-Nov"
   │  ├─ "Compara Octubre vs Noviembre"
   │  └─ "¿Qué host tiene más problemas HIGH?"
   └─ Histórico ilimitado para tendencias

5. REPORTES (report.py)
   ├─ CSV: Tabla Excel con todos los hallazgos
   ├─ PDF: Reporte ejecutivo con:
   │  ├─ Resumen de severidades (HIGH: 5, MEDIUM: 12, LOW: 3)
   │  ├─ Gráfico de tendencias (últimos 30 días)
   │  ├─ Gráfico de pastel (distribución de severidades)
   │  └─ Top 10 hallazgos más críticos
   └─ PDF Comparativo: Compara dos períodos con deltas

6. INTERFAZ GRÁFICA (ver_reporte.py)
   ├─ Menú para ejecutar escaneos
   ├─ Visualizar reportes generados
   ├─ Ver estadísticas de la BD
   └─ Generar comparativas por fechas

CONFIGURACIÓN INICIAL (SOLO UNA VEZ)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PASO 1: Instalar NMAP
   ▸ Descargar: https://nmap.org/download.html
   ▸ Instalar en: C:\Program Files (x86)\Nmap\
   ▸ Verificar: Abrir CMD y escribir "nmap --version"

PASO 2: Verificar Entorno Virtual Python
   ▸ Ya tienes .venv creado
   ▸ Dependencias instaladas:
     - python-nmap (para escaneos)
     - SQLAlchemy (base de datos)
     - matplotlib (gráficos)
     - reportlab (PDFs)
     - tkcalendar (selector de fechas)

PASO 3: Configurar Targets (¿Qué escanear?)
   ▸ Abrir: config/targets.yaml
   ▸ Ejemplo:

     targets:
       - cidr: "192.168.1.0/24"    # Toda tu red local
         env: "oficina"
       - host: "192.168.1.100"     # Un servidor específico
         env: "servidor-web"

   ▸ CIDR = rango de IPs (192.168.1.1 a 192.168.1.254)
   ▸ Host = IP individual

PASO 4: Configurar Reglas (¿Qué es peligroso?)
   ▸ Abrir: config/rules.yaml
   ▸ Ejemplo:

     deny_ports: [21, 23, 3389]   # FTP, Telnet, RDP prohibidos
     
     min_versions:
       ssh: "OpenSSH_8.0"          # Versión mínima aceptable
     
     tls:
       forbid_protocols: 
         - "SSLv3"                 # Protocolos obsoletos
         - "TLS1.0"
         - "TLS1.1"

   ▸ Si detecta estos problemas → Marca como HIGH/MEDIUM

ARCHIVO CSV (findings_TIMESTAMP.csv)
═════════════════════════════════════════════════════════════════════════

Columnas:
  host        → IP del dispositivo (ej: 192.168.1.50)
  port        → Puerto abierto (ej: 23 = Telnet)
  service     → Tipo de servicio (ssh, http, ftp, etc.)
  product     → Software específico (OpenSSH, Apache, etc.)
  version     → Versión del software (7.4p1, 2.4.41, etc.)
  env         → Entorno (lab, producción, etc.)
  severity    → Criticidad (HIGH, MEDIUM, LOW)
  reasons     → Por qué es problema (["Puerto prohibido 23"])
  status      → NEW (nuevo), CHANGED (modificado), SAME (igual)

Ejemplo de fila:
  192.168.1.100, 23, telnet, , , lab, HIGH, ["Puerto prohibido 23"], NEW

Qué hacer:
  ✓ HIGH → Arreglar INMEDIATAMENTE (puertos peligrosos)
  ✓ MEDIUM → Arreglar esta semana (versiones viejas)
  ✓ LOW → Planificar corrección
  ✓ Filtrar por host para ver todos los problemas de un servidor

  1. Configurar rules.yaml según estándar (PCI-DSS, ISO 27001, etc.)
  2. Escaneo mensual
  3. Generar comparativa mes actual vs mes anterior
  4. Adjuntar PDF comparativo a reporte de compliance
  5. Demostrar mejora continua

CASO 3: Post-Incidente
  1. Después de ataque/brecha de seguridad
  2. Ejecutar escaneo inmediatamente
  3. Comparar contra último escaneo "bueno"
  4. Identificar qué cambió (puertos nuevos, servicios nuevos)
  5. Remediar y validar con nuevo escaneo

CASO 4: Hardening de Servidores
  1. Escaneo inicial (baseline)
  2. Aplicar configuraciones de seguridad
  3. Escaneo post-hardening
  4. Comparativa antes/después
  5. Validar que HIGH bajaron a cero

CASO 5: Monitoreo Continuo
  1. Programar escaneos automáticos (ejecutar.bat en Programador de Tareas)
  2. Revisar PDFs diariamente
  3. Usar "Ver Estadísticas" para tendencias
  4. Alertar si HIGH aumenta semana a semana

SOLUCIÓN DE PROBLEMAS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PROBLEMA: "nmap no reconocido como comando"
  ✓ Solución: Instalar Nmap desde https://nmap.org/download.html
  ✓ Agregar C:\Program Files (x86)\Nmap\ al PATH de Windows
  ✓ Reiniciar terminal

PROBLEMA: "No se puede abrir archivo .db"
  ✓ Solución: El programa lo crea automáticamente en primer escaneo
  ✓ Si persiste: Borrar data/bluebot.db y volver a ejecutar

PROBLEMA: Escaneo tarda mucho
  ✓ Reducir rango de IPs en targets.yaml
  ✓ Escanear solo IPs específicas en vez de CIDR completo
  ✓ Usar -T4 (ya configurado) es el modo rápido de nmap

PROBLEMA: Dashboard web no inicia
  ✓ Verificar que Flask esté instalado:
    ..\.venv\Scripts\pip.exe list | findstr Flask
  ✓ Instalar si falta: ..\.venv\Scripts\pip.exe install flask
  ✓ ERROR COMÚN: "get_statistics is an unknown import symbol"
    → Solución: Asegúrate de tener la última versión de src/db/__init__.py
    → La función get_statistics debe estar exportada en __all__
  ✓ Verificar puerto 5000 no esté en uso:
    netstat -ano | findstr :5000
  ✓ Revisar firewall de Windows si accedes desde otra PC

PROBLEMA: No se ven gráficos en dashboard
  ✓ Verificar conexión a internet (usa CDN para Chart.js)
  ✓ Abrir consola del navegador (F12) para ver errores
  ✓ Verificar que existan datos en la BD (ejecutar escaneo primero)
  ✓ Usar -T4 (ya configurado) es el modo rápido de nmap

PROBLEMA: No se generan gráficos en PDF
  ✓ Verificar que matplotlib esté instalado:
    ..\.venv\Scripts\pip.exe list | findstr matplotlib
  ✓ Necesitas al menos 1 escaneo previo para tendencias
  ✓ Revisar logs en consola por errores

PROBLEMA: "No se pudo guardar en BD"
  ✓ Verificar que carpeta data/ exista
  ✓ Verificar permisos de escritura
  ✓ Revisar log de error específico

PROBLEMA: Comparativa no muestra datos
  ✓ Necesitas al menos 2 escaneos en los rangos seleccionados
  ✓ Verificar fechas: deben existir escaneos en esas fechas
  ✓ Revisar data/bluebot.db tiene registros

  1. cd infra/
  2. docker-compose up -d
  3. Contenedor ejecuta escaneos en segundo plano
